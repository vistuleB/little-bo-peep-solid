# little-bo-peep-solid — SolidJS Interactive Textbook

## Start Here: Writerly Library

Before working in this repo, read `../wly/CLAUDE.md` (sibling directory). That file documents:
- The **Writerly** markup language (`.wly` syntax, multi-file assembly, `WriterlyBlankLine` / `WriterlyCodeBlock` / `WriterlyComment` nodes)
- The **VXML** AST (`V` and `T` nodes, `Blame`, `Attr`, `Line`)
- The **desugaring** library — `Desugarer`, `Pipeline`, `Renderer`, and the full data-flow:
  ```
  Writerly source → List(InputLine) → VXML → VXML (pipeline) → List(OutputFragment) → .tsx files
  ```
- The `desugarer_library` API (`dl.*`) and how to read individual desugarer files

## What This Repo Does

`little-bo-peep-solid` is a **consumer project** of the Writerly/desugaring stack. It renders an
interactive mathematics textbook ("Little Bo Peep") written in Writerly markup into a
**SolidJS / SolidStart** single-page application with pre-rendering.

The repo has two distinct halves that must be kept in sync:

| Half | Language | Directory | Purpose |
|---|---|---|---|
| **Gleam renderer** | Gleam | `renderer/` | Reads `.wly` source → emits `.tsx` files into `src/` |
| **SolidJS front-end** | TypeScript / SolidJS | `src/` | Static components + generated routes served by SolidStart |

The Writerly/desugaring library lives at `../wly/` (sibling to this repo). It is imported as a
local Gleam dependency in `renderer/gleam.toml`.

## Source (`src/content/`) layout

Unlike the `dr` project (which uses numbered subdirectories for chapters), this project uses a
**flat file** layout with naming conventions:

```
src/content/
├── __parent.wly          # Root: Book node + HeaderBlob + ChapterSelection + In nodes
│                         #   In nodes control which exercises appear in which chapter
├── ch1__parent.wly       # Chapter 1 node: title, handle, page attrs
├── ch1.wly               # Chapter 1 body: Sections
├── ch1^exercises/        # Chapter 1 exercises (dir whose name starts with ch1^)
│   ├── __parent.wly      # Exercises node
│   └── _exercise_name_.wly  # One exercise per file (names wrapped in underscores)
├── bt1__parent.wly       # Bootcamp 1 node
├── bt1.wly               # Bootcamp 1 body
├── bt2^exercises/        # Bootcamp 2 exercises
├── appendixA__parent.wly
├── appendixA.wly
└── ...
```

Key structural tags in `.wly` source:
- `|> Book` — root document node (in `__parent.wly`)
- `|> HeaderBlob` — custom header content (logo, loading image, etc.)
- `|> ChapterSelection` — declares which chapters/bootcamps are present and their order
- `|> In chapter=>>handle ...` — assigns exercise handles to a chapter
- `|> Chapter handle=... title=...` — a chapter (in `ch*__parent.wly`)
- `|> Bootcamp handle=... title=...` — a bootcamp (in `bt*__parent.wly`)
- `|> Appendix handle=... title=...` — an appendix
- `|> Section handle=... id=...` — a section within a chapter/bootcamp
- `|> Example` / `|> Note` / `|> SolutionNote` — numbered content blocks
- `|> Exercises` / `|> Exercise` / `|> Solution` — exercise blocks
- `|> Image` / `|> ImageRight` / `|> ImageLeft` / `|> InlineImage` — images
- `|> Grid` — side-by-side columns
- `|> CentralDisplay` / `|> CentralDisplayItalic` — centered display blocks (use `_|...|_` / `__...__` delimiters)
- `|> List` / `|> Item` — custom list (separate from `ol`/`ul`)

Handles (e.g. `handle=refreshers`, referenced as `>>refreshers`) are used for cross-referencing
chapters, exercises, and sections. The pipeline resolves them into links via
`dl.writerly_handles_add_ids` + `dl.writerly_handles_substitute_and_fix_nonlocal_id_links`.

Files and directories whose names start with `#` are Writerly comments (ignored by the assembler).
The `>>` prefix is the Writerly handle reference syntax.

## Commands

### Run the Gleam renderer

```sh
cd renderer
gleam run
```

This reads `src/content/`, runs the desugaring pipeline, and writes generated `.tsx` files
directly into `src/routes/` and `src/components/`. **The generated files are the SolidJS source.**

Common flags:
| Flag | Effect |
|---|---|
| `--only <id> [<id>...]` | Render only the named chapter(s)/bootcamp(s) by handle |
| `--only <id> key=val` | Render only elements within `<id>` that have attribute `key=val` |
| `--local` | Author mode: add source-linking tooltips (requires local dev server) |
| `--clean` | Remove unused images from `image-map.json` and `build-img/` |
| `--last-command` | Re-run the previous command (stored in `.last-command`) |
| `--help` | Basic usage |
| `--esoteric` | Advanced/esoteric CLI options |

Example (render only chapter 5 with a working marker):
```sh
gleam run -- --only ch5 work=ing --local
```

### Run the local dev server

```sh
npm run dev          # serves on localhost:3000
```

Or configure via `.env`:
```
VITE_ENV=DEV
AUTHOR_MODE=true
OFFLINE_MODE=false
MATHJAX_VERSION=3
```

### Build for production

```sh
npm run build
npm run start
```

### Install local MathJax assets (offline mode)

```sh
npm run build-local-mathjax
```

Copies MathJax v3 and v4 into `public/mathjax3/` and `public/mathjax4/`.

## Pipeline (`renderer/src/pipeline.gleam`)

`pub fn our_pipeline(only: Bool, remove_unused: Bool, author_mode: Bool) -> Pipeline`

The pipeline transforms the assembled VXML tree into JSX-ready VXML. Key stages in order:

1. **Cleanup** — `delete("WriterlyComment")`, drop `!!`-prefixed attributes
2. **Exercise grouping** — `wrap_if_not_child_of("Exercise", "Exercises")` ensures every loose `Exercise` is wrapped in an `Exercises` container; then `lbp_*` desugarers reorganize exercises into per-chapter "graveyards" and re-attach them via `In` nodes
3. **Content selection** — `lbp_select_content()` filters which chapters/exercises are included based on the `ChapterSelection` / `In` declarations in `__parent.wly`
4. **Auto-generate titles** — `auto_generate_child_if_missing_from_attribute__outside` for `Chapter`, `Bootcamp`, `Appendix` → `ArticleTitle`
5. **Math block parsing** — `syntax.create_mathblock_elements` (`$$` delimiters)
6. **Inline math parsing** — `syntax.create_math_elements` (`$` delimiters)
7. **Markdown link splitting** — `syntax.markdown_link_pipeline` (skips math)
8. **Escaped dollar sign** — `find_replace__outside("\\$", "$")`
9. **Counters** — appends counter attributes to `Book`, `Chapter`, `Bootcamp`, `Appendix`, `Exercises`, `Section`, `Example`, `Note`, `SolutionNote`, `Exercise`; increments: `ChapterCounter`, `BootcampCounter`, `AppendixCounter`, `ExampleCounter`, `NoteCounter`, `SectionCounter`, `ExerciseCounter`, `SolutionNoteCounter`
10. **Path/banner/number attributes** — `append_attribute__outside` injects `path`, `banner`, `number`, `category` onto `Chapter`, `Bootcamp`, `Appendix`
11. **Counter text injection** — `prepend_text_node` for `Example`, `Note`, `SolutionNote`, `Exercise`
12. **Handle system** — `set_handle_value` → `writerly_handles_add_ids` → `writerly_handles_generate_dictionary_and_id_list` → `writerly_handles_substitute_and_fix_nonlocal_id_links` (turns `>>handle` references into `<InChapterLink>` or `<a>` cross-links)
13. **Table markup** — `table_marker()`
14. **Paragraph grouping** — `group_consecutive_children__outside("p", p_cannot_contain)`
15. **List wrapping** — `wrap_children_avoiding("List", "Item", "WriterlyBlankLine")`
16. **Blank line / p cleanup** (first pass)
17. **Central display splitting** — `__...__` → `CentralDisplayItalic`; `_|...|_` → `CentralDisplay`; `free_children` frees any `p` inside these
18. **Italic/bold splitting** — `permissive_symmetric_delimiter_pipeline` for `_..._` → `i` and `*...*` → `b`
19. **Escaped delimiters** — `find_replace__outside("\\*","*")`, `find_replace__outside("\\_","_")`
20. **p cleanup** (second pass) — trim, delete empty, unwrap if no inline children, unwrap inside `td`/`li`, rename `p` to `Item` if inside `Grid`
21. **Exercise statement wrapping** — `wrap_children_up_to("Exercise", "Solution", "ExerciseStatement")`
22. **Image absorption** — `absorb_into_previous_sibling(["ImageRight","ImageLeft"])`
23. **Pause insertion** — `add_between_all_pairs_2` and `add_before_but_not_before_first_child__batch` inserts `Pause` (spacers) between block elements
24. **OuterP renaming** — `rename_if_child_of_one_of("p", "OuterP", [section-like containers])`
25. **Link rearrangement** — `rearrange_links_4_pre_tokenized_src__batch` normalizes "Chapter N", "Exercise N of Chapter M" etc. link patterns
26. **TOC / hamburger panel generation** — `lbp_generate_table_of_contents` for both `TOC` and `HamburgerPanelAuthorSuppliedContents`
27. **Prev/next navigation** — `lbp_generate_prev_next_attributes()`
28. **Breadcrumbs** — `lbp_generate_breadcrumbs()`
29. **Attribute cleanup** — deletes `counter`, `handle`, `t`, `_`, `title`, `test`; renames remaining attributes to camelCase (`kabob_case_to_camel_case`)
30. **Author mode** (when `--local`) — `lbp_turn_lines_into_3003_spans__outside` and `lbp_adorn_img_with_3003_spans` add source-linking tooltips
31. **Image build** — `lbp_img_build` processes images in `images/` into `public/` via the `build-img` tool, updating `image-map.json`
32. **src normalization** — `ensure_attribute_value_starts_with("src", "/")`

## Renderer (`renderer/src/renderer.gleam`)

`pub fn main()` — entry point. Wires together:

```
assembler  : default_writerly_assembler   (reads src/content/)
parser     : default_writerly_parser
filterer   : default_filterer             (ignores In, HeaderBlob, ChapterSelection control nodes by default)
pipeline   : our_pipeline(only, remove_unused, author_mode)
splitter   : our_splitter
emitter    : our_emitter(_, imports_lookup)
writer     : default_writer
prettifier : default_prettier_prettifier  (runs prettier on output .tsx)
```

### Splitter (`our_splitter`)

Splits the VXML tree into four fragment types:

| Fragment type | Output path | Content |
|---|---|---|
| `TOC` | `src/routes/index.tsx` | Table of contents page |
| `HamburgerPanelAuthorSuppliedContents` | `src/components/HamburgerPanelAuthorSuppliedContents.tsx` | Nav panel content |
| `HeaderBlob` | `src/components/HeaderBlob.tsx` | Header graphic/content |
| `Article(funcname)` | `src/routes/article/<path>.tsx` | One file per Chapter/Bootcamp/Appendix |

Article paths are derived from the `path` attribute set by the pipeline (e.g. `/article/chapter1`
→ `src/routes/article/chapter1.tsx`). The exported function name is derived from `category` +
`number` (e.g. `__Chapter1__`).

### Emitter (`our_emitter`)

- **`article_emitter`** — emits a SolidJS page component. The article VXML is split at the
  first `Section`: content up to and including the first section renders immediately; remaining
  sections are wrapped in a `<Rest>` component that is conditionally shown via `useShowMore()`.
  Auto-generates import statements by scanning VXML for uppercase tag names and resolving them
  via `emitter_imports.gleam`.
- **`toc_emitter`** — emits the `__Home__` index page component with `useNoScrollRestoration`.
- **`standard_component_emitter`** — emits `HamburgerPanelAuthorSuppliedContents` and `HeaderBlob`
  as simple functional components.

### Import resolution (`renderer/src/emitter_imports.gleam`)

`lbp_exports_dictionary()` maps each component file (e.g. `"Wrappers"`) to the list of VXML tags
it exports (e.g. `["Section", "Note", "SolutionNote", "Example", "NoBreak", "Pause", ...]`).
The emitter scans the output VXML for uppercase tag names and auto-generates the correct
`import ... from "~/components/..."` lines at the top of each `.tsx` file.

**When adding a new SolidJS component that corresponds to a VXML tag, you must add it to
`lbp_exports_dictionary()` in `emitter_imports.gleam`.**

## SolidJS Front-end (`src/`)

The front-end is a **SolidStart** (file-based routing) app with **Tailwind CSS** and
**MathJax** for math rendering. SSR is disabled (`ssr: false` in `app.config.ts`); the site
is pre-rendered at build time via `prerender: { crawlLinks: true }`.

Key architectural points:
- `src/app.tsx` — wraps everything in `<MetaProvider>`, `<StoreProvider>`, `<Router>`, `<HeaderButtons>`, `<Container>`
- `src/routes/article.tsx` — layout wrapper for all `/article/*` routes; adds `<SVGDefs>`
- `src/routes/article/*.tsx` — **generated files** — do not edit by hand; re-run the renderer
- `src/routes/index.tsx` — **generated file** — TOC page
- `src/components/HamburgerPanelAuthorSuppliedContents.tsx` — **generated file**
- `src/components/HeaderBlob.tsx` — **generated file**
- All other `src/components/*.tsx` files — **manual** — edit these to change how tags render
